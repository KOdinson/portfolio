Stop reading alerts. Start closing cases.

Triage groups alerts that belong to the same incident, tells you why it grouped them, and lets you turn the grouping off whenever you want to check its work.

Try the prototypeHow it works

Live prototype with invented data. Press J and K to move, E to escalate, C to close.

The problem

Rules fire on events. People attack in sequences.

A flat list sorted by time scatters one incident across the screen and mixes it with routine noise. The analyst is left to notice that rows 3, 9, 14 and 22 are the same story.

How it works

Three ideas, each one checkable.

Grouping that explains itself

Every case opens with "Why these are together" in a sentence or two. If the tool merged things that do not belong, you can see the reasoning and reject it.

An off switch

One toggle returns the flat list. An alert with relatives elsewhere says so. Trust is built by being able to check.

A reason on every close

Closing a case asks why it is safe, on keys 1 to 4. One extra keystroke, and the answer is the data someone needs to fix a noisy rule.

Hands on the keyboard

Every shortcut is printed on its button.

You learn the keys by using the mouse, and then you stop needing the mouse.

What this is not

A design for the queue, with no engine behind it.

  • It does not collect logs or detect anything.
  • The grouping rule is the simplest possible: same machine or same account.
  • It has not been used by working analysts.

The interface argument stands either way: however alerts are grouped, the grouping needs a stated reason and an off switch.
